# 팀 Todo CLI 제품 요구사항 (PRD)

## 1. 개요

`ttodo`는 로컬 Team Todo API를 터미널에서 사용할 수 있게 하는 크로스플랫폼 CLI다. 터미널 명령을 익숙하게 사용하지 않는 팀원도 Todo 생성, 조회, 수정, 삭제를 실행할 수 있어야 한다. 별도 대화형 입력 없이 명령과 옵션으로 작업을 완료한다.

## 2. 목표

- macOS, Linux, Windows에서 같은 CLI 명령을 사용할 수 있다.
- `uvx`를 통해 별도 프로젝트 환경 설치 없이 CLI를 실행할 수 있다.
- Todo API의 모든 엔드포인트와 목록 필터를 명령으로 제공한다.
- 기본 출력은 읽기 쉬운 텍스트로 제공하고 자동화를 위해 JSON 출력도 제공한다.
- CLI의 모든 도움말은 비개발자가 이해할 수 있는 plain English로 작성한다.

## 3. 사용자와 사용 환경

- 사용자는 개발자가 아닐 수 있으며 Python 코드나 HTTP API를 직접 다루지 않는다.
- CLI는 로컬 네트워크의 Todo API를 호출한다. 기본 API 주소는 `http://127.0.0.1:8000`이다.
- `uv`가 설치되어 있으면 저장소에서 `uvx --from . ttodo --help`로 시작할 수 있다. `uvx`는 패키지 실행 환경을 관리하며 별도의 대화형 설정은 요구하지 않는다.
- API에는 인증 기능이 없으므로 서버 접근 가능 범위와 보안 전제는 백엔드 PRD를 따른다.

## 4. 범위

### 포함

- Todo 생성, 목록 조회, 단건 조회, 부분 수정, 삭제
- 목록 필터: 상태, 담당자, 우선순위, 마감일 시작·종료, 태그
- 목록 페이지네이션: `limit`, `offset`
- 사람이 읽기 쉬운 기본 텍스트 출력과 `--json` 출력
- 기본 API 주소 변경을 위한 `--base-url` 옵션과 `TEAM_TODO_BASE_URL` 환경 변수
- macOS, Linux, Windows에서의 실행 및 사용 문서

### 제외

- 로그인, 인증, 권한 관리
- 대화형 프롬프트, 메뉴, 터미널 UI
- OpenAPI 문서를 실행할 때 내려받아 명령을 동적으로 생성하는 기능
- Todo 데이터의 로컬 저장 또는 서버와의 오프라인 동기화
- 백엔드 API에 정의되지 않은 추가 기능

## 5. 명령과 사용자 시나리오

CLI 이름은 `ttodo`이며 명령은 API 리소스를 기준으로 구성한다.

| 명령 | 동작 |
|---|---|
| `ttodo create` | Todo를 생성한다. 제목을 받고 선택 필드를 옵션으로 받는다. |
| `ttodo list` | Todo 목록을 조회하고 필터와 페이지네이션을 적용한다. |
| `ttodo get <id>` | Todo 한 건을 조회한다. |
| `ttodo update <id>` | 전달한 필드만 수정한다. |
| `ttodo delete <id>` | Todo와 태그 연결을 삭제한다. 연결이 없는 태그 이름은 이후 재사용할 수 있도록 보존한다. |

일반 사용자는 도움말에서 가능한 명령과 옵션을 확인하고, 필요한 필드만 입력해 작업한다. 상세 명령 옵션과 예시는 `TSD_CLI.md`에 정의한다.

### API 엔드포인트 대응

현재 OpenAPI 스키마의 모든 애플리케이션 엔드포인트를 CLI에 제공한다. 현재 API는 아래 다섯 작업으로 구성된다.

| HTTP 작업 | CLI 명령 |
|---|---|
| `POST /api/v1/todos` | `ttodo create` |
| `GET /api/v1/todos` | `ttodo list` |
| `GET /api/v1/todos/{todo_id}` | `ttodo get <id>` |
| `PATCH /api/v1/todos/{todo_id}` | `ttodo update <id>` |
| `DELETE /api/v1/todos/{todo_id}` | `ttodo delete <id>` |

목록 엔드포인트의 모든 query parameter를 지원한다. OpenAPI에서 새 애플리케이션 엔드포인트나 매개변수가 추가되면 이에 대응하는 CLI 동작과 테스트 케이스도 함께 추가한다. `/docs`, `/redoc`, `/openapi.json`은 문서용 경로이며 Todo 작업 명령으로 취급하지 않는다.

## 6. 기능 요구사항

- CLI는 백엔드 API의 검증 규칙, enum, 날짜 형식, 기본값 및 오류 상태 코드를 따른다.
- 생성·수정에 대화형 입력을 요구하지 않는다. 필요한 값이 없거나 올바르지 않으면 사용법 또는 유효성 오류를 알기 쉬운 문장으로 표시한다.
- 수정 시 생략한 필드는 기존 값을 유지한다. nullable 값 비우기와 태그 전체 제거는 명시적인 옵션으로 표현한다.
- 삭제는 확인 프롬프트 없이 실행한다.
- 기본 출력은 사람이 읽을 수 있어야 한다. `--json`을 지정하면 결과 데이터를 JSON으로 출력한다.
- 요청 실패 시 오류 원인과 가능한 조치를 표시하고 성공처럼 보이는 출력을 하지 않는다.
- `ttodo --help`와 모든 명령의 `--help`는 plain English를 사용한다. 문장은 짧고 일상적인 단어를 쓰며, HTTP, endpoint, payload, enum, pagination 같은 개발자 용어를 사용자 설명에 사용하지 않는다.
- 도움말은 각 명령이 하는 일, 필요한 정보, 선택할 수 있는 값, 기본 동작, 자주 쓰는 예시를 설명한다. 필드명과 실제 입력값은 API 호환성을 위해 그대로 표기하되 뜻을 쉬운 영어로 설명한다.

## 7. 완료 기준

- OpenAPI의 다섯 애플리케이션 작업과 목록의 모든 query parameter가 CLI에 대응하고, 각 대응은 테스트로 검증된다.
- 목록 필터와 페이지네이션을 CLI 옵션으로 전달할 수 있다.
- 기본 텍스트와 JSON 출력이 각각 동작한다.
- API 주소를 기본값, 명령 옵션 또는 환경 변수로 지정할 수 있다.
- macOS, Linux, Windows에서 `uvx --from . ttodo --help`와 API 명령을 실행할 수 있다.
- 루트 도움말과 각 명령 도움말이 plain English로 비개발자에게 필요한 사용법을 설명한다.
- CLI 사용·설치 전제·명령 예시가 `TSD_CLI.md`에 문서화되고 검증 시나리오가 `TEST_CASE_CLI.md`에 정의된다.
