# 보안 감사 보고서

- 감사일: 2026-10-07
- 대상: 현재 저장소의 FastAPI Todo API, SQLAlchemy/SQLite 접근, 설정·마이그레이션, CI 및 런타임 의존성
- 기준: 저장소가 의도한 신뢰된 로컬 개발 환경
- 판정: **로컬 전용 사용에는 수용 가능, 네트워크 공개 운영에는 부적합**

## 요약

소스 검토에서 인증을 우회하거나 SQL을 주입할 수 있는 경로는 확인하지 못했다. 요청은 Pydantic 스키마와 길이·enum 검증을 거치고, DB 질의는 SQLAlchemy 표현식으로 구성된다. 오류 응답은 무결성 오류를 일반적인 `409`로 바꾼다. 런타임 의존성은 lockfile에서 추출해 `pip-audit`로 확인했으며, 2026-10-07 기준 알려진 취약점은 보고되지 않았다.

서비스는 인증 및 권한 검사를 제공하지 않는다. 이는 PRD의 범위와 일치하지만, 서버를 loopback 밖에 바인딩하면 네트워크에 접근 가능한 누구나 모든 Todo를 읽고 바꿀 수 있다. 이 API는 신뢰된 로컬 환경에서만 실행해야 한다.

## 발견 사항

### SEC-01 — 인증·권한 검사가 없음

- 심각도: **중간** (외부 인터페이스에 노출되면 높음)
- 근거: API 경로 전체에 인증 의존성이나 사용자별 권한 검사가 없다. README 실행 예시는 `127.0.0.1`에 바인딩한다.
- 영향: 다른 호스트에서 접근 가능한 주소로 바인딩하거나 프록시를 통해 공개하면, 접근자가 Todo를 조회·생성·수정·삭제할 수 있다.
- 권고: loopback 바인딩을 유지한다. LAN/인터넷 운영 전에 인증, 권한, TLS 및 접근 제한을 설계하고 적용한다.
- 상태: PRD가 인증 없는 로컬 MVP를 명시하므로 코드 변경 대상은 아니며, 배포 경계에 관한 제한이다.

### SEC-02 — 요청 본문 및 태그 배열의 상한이 없음

- 심각도: **중간**
- 근거: 제목·설명·담당자·태그 문자열은 길이를 제한하지만 `tags` 배열의 원소 수와 HTTP 본문 크기는 제한하지 않는다. 생성 요청의 알 수 없는 필드는 Pydantic 기본 설정상 무시된다.
- 영향: 큰 JSON 본문이나 과도한 태그 수가 파싱 메모리와 CPU, 태그 DB 작업량을 크게 늘릴 수 있다. 로컬 신뢰 모델에서는 제한적이나 API를 네트워크에 노출하면 서비스 거부 위험이 커진다.
- 권고: `tags`에 최대 원소 수를 지정하고, ASGI 서버 또는 앞단 프록시에서 요청 본문 크기를 제한한다. 생성 스키마도 `extra="forbid"`로 설정해 잘못된 필드를 거부하는 방안을 검토한다.
- 상태: 개선 권고.

### SEC-03 — `.env` 파일이 Git 제외 목록에 없음

- 심각도: **낮음**
- 근거: 설정은 `.env`를 읽을 수 있지만 `.gitignore`는 `.env`를 제외하지 않는다.
- 영향: 향후 DB URL에 자격 증명이나 기타 비밀 값을 넣으면 실수로 커밋될 수 있다.
- 권고: `.env`와 필요한 변형 파일을 Git 제외 목록에 추가하고, 저장소에는 비밀이 없는 `.env.example`만 둔다.
- 상태: 개선 권고.

### SEC-04 — CI에 자동 의존성 취약점 검사가 없음

- 심각도: **낮음**
- 근거: GitHub Actions는 lockfile 설치, Ruff, 테스트를 실행하지만 CVE 감사 단계를 실행하지 않는다.
- 영향: 현재 의존성이 안전하더라도 이후 취약점 공개 시 자동으로 발견되지 않는다.
- 권고: CI 또는 정기 작업에 lockfile 기반 취약점 검사를 추가하고, 업데이트 PR과 함께 결과를 검토한다.
- 상태: 개선 권고.

## 확인한 방어 수단

- SQL 질의는 ORM/바인딩된 표현식을 사용한다. 문자열 SQL을 사용자 입력으로 조립하는 경로는 확인하지 못했다.
- 제목, 설명, 담당자, 태그 길이와 상태·우선순위 enum을 검증한다. 페이지 크기는 최대 100이다.
- DB 무결성 오류는 내부 DB 세부 정보 대신 일반적인 `409`를 반환한다.
- SQLite 외래 키 검사가 연결마다 켜진다. 세션은 요청 종료 시 닫힌다.
- GitHub Actions 권한은 `contents: read`이며 checkout/setup 액션은 커밋 해시로 고정돼 있다.
- `uv.lock`에 의존성 버전과 해시가 고정돼 있다.

## 의존성 검사

`uv export --locked --no-dev --format pylock.toml`로 런타임 lock을 내보낸 뒤 `pip-audit`를 실행했다. 결과는 **No known vulnerabilities found**였다. 개발 의존성은 이 런타임 검사에 포함하지 않았다. 취약점 DB와 패키지 상태는 바뀔 수 있으므로 이 결과는 감사일 기준 스냅샷이다.

## 범위와 한계

이번 검토는 정적 코드·설정 검토와 런타임 의존성 CVE 조회다. 침투 테스트, 컨테이너/호스트 구성, 실제 인터넷 노출 경로, SQLite 파일 시스템 권한, 비밀 회전 절차는 검증하지 않았다. 따라서 이 보고서는 외부 보안 인증이나 운영 환경 보증을 의미하지 않는다.
